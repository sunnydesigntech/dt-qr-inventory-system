01 · Summary of changes

This pass replaces the existing code.gs web-app render with a complete UI system: a navigable landing dashboard, a two-mode storage page (View / Tech), an admin readiness screen, a printable QR-label sheet, and a diagnostics panel. Everything is server-rendered from one Apps Script file — no separate HTML/CSS/JS tracked, per repo policy.

Wins

  • Mobile-first cards with 44 px hit targets — works on a phone in the workshop.
  • Tech Mode batch-save with sticky save bar, dirty-state badges, optimistic UI & rollback toast.
  • Readiness scoring (errors × 8 + warnings × 1, capped 0–100) surfaces blockers before rollout.
  • Zero-config browsing: in-app links are relative, so the app runs without WEB_APP_BASE_URL.
  • Printable QR label sheet (A4, 2-up) with hazard treatment.

Caveats

  • QR generation still requires WEB_APP_BASE_URL; in-app navigation does not.
  • Tailwind is loaded via CDN — fine inside an Apps Script HtmlService iframe, but degrades to unstyled HTML if blocked. Critical layout uses base CSS that survives.
  • No offline queue yet — Tech Mode saves require an open round-trip to Apps Script.
  • Audit trail (timestamp + user + before/after) is out of scope for this pass.

04 · Screens shipped

4.1 Landing

Mobile-first storage grid; desktop adds a sticky right rail with readiness + config. Storage cards expose two primary actions — View / Tech — without hiding either behind a menu. Hazard storages get a red icon chip and pill so a technician spots chemical cabinets at a glance.

4.2 Storage page · View Mode

Read-only. Hero summarises room, label, IDs, item/chemical/attention counts. Each item shows quantity + status as a self-contained tile. A status-breakdown sidebar appears on desktop only — mobile collapses to the list.

4.3 Storage page · Tech Mode

Same shell as View Mode but each row exposes a stepper-input quantity and a status select. Edits are tracked client-side; the sticky save bar shows the unsaved-change count and a Save / Reset pair. Saving sends the diff array via google.script.run.applyInventoryUpdates; the server validates qty (≥ 0, finite) and status (whitelist) per row.

4.4 Admin · Readiness

Top card: SVG gauge + score (errors × 8 + warnings × 1). Six tiles: errors, warnings, missing QR, missing storage IDs, invalid quantities, duplicates. The 419A rollout strip mirrors the landing hero. Sidebar lists actionable next steps that change with the data.

4.5 Admin · QR Labels

A4 print preview, 2-up. Each label: VSA D&T eyebrow · storage name · specific location · monospaced storage-ID badge · scan-to-view caption · faint URL footer. Hazard cabinets get a tinted background and PPE caption. Print stylesheet hides chrome and sizes to @page A4 / 8 mm.

4.6 Admin · Diagnostics

One row per config check: green = ok, amber = optional missing, red = critical missing. Every failed check ships an inline How to fix hint pointing at the spreadsheet menu — no chasing through README. Sidebar lists what works without WEB_APP_BASE_URL vs. what requires it.

05 · Data flow & save bridge

Read path

  1. doGet reads script properties → opens spreadsheet → reads Inventory sheet (or override).
  2. readInventoryRows_ builds {headers, rows} with each row tagged with its sheet row number.
  3. rowToItem_ normalises types (qty → number, hazard → boolean, status → trimmed string).
  4. buildBootstrapData_ aggregates per-storage / per-room stats, sorts 419A first, computes readiness.
  5. Server emits a fully rendered HTML string — no client-side fetch.

08 · Test plan / smoke checks

Pre-rollout (every push)

  1. Landing renders; rollout hero shows 419A percent > 0.
  2. Room chips filter the grid; "All rooms" restores it.
  3. Storage search matches by ID, label, code, room — case-insensitive.
  4. Storage card · View link opens the View Mode page.
  5. Storage card · Tech Update opens Tech Mode (page tint changes).
  6. View Mode · status filter narrows the list.
  7. Tech Mode · stepper buttons clamp at 0.
  8. Tech Mode · changing qty or status flips the row to dirty + amber badge.
  9. Tech Mode · Save → green toast, dirty count → 0, originals updated.
  10. Tech Mode · Reset reverts every dirty row.
  11. Spreadsheet → confirm the rows actually changed.
  12. Readiness score reflects current state; 419A rollout panel matches landing.
  13. QR Labels print preview · Cmd-P shows 2-up A4 with no chrome.
  14. Diagnostics shows green for SPREADSHEET_ID, amber/red elsewhere with fix copy.
  15. Bad URL · ?room=419A&loc=DOES-NOT-EXIST renders the friendly not-found state.

Edge cases worth poking

  • Storage that exists in the master but has zero items → empty-state card.
  • Item row with non-whitelist status → counted as a warning; rendered with neutral pill.
  • Item row with negative or non-numeric qty → counted as an error.
  • Viewport at 360 px — every screen should fit without horizontal scroll.
  • Long storage label / long item name — should ellipsize, not break the card.

09 · Known limits & rollback

  • Last-write-wins. Two technicians editing the same row clobber each other.
  • Tailwind CDN dependency. CDN unreachable → degraded styling but layout still legible (base CSS handles structure).
  • No client-side caching. Every page is a server render; large sheets (> 5 000 rows) may hit Apps Script's 6-minute execution cap. 419A is well under.
  • No audit trail on save (intentional — backlogged).

Rollback

# If something goes sideways:
# 1. Apps Script editor → Deploy → Manage deployments → version @2
# 2. Or redeploy the previous code.gs from clasp/git
